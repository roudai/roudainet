# メガミンクス PLL の質問に答える

メガミンクスの PLL について聞かれたら、**記事の知識**と**計算**の 2 つだけに基づいて答える。

- **記事**:roudai.net の「Megaminx PLL」(https://roudai.net/megaminx/megaminx-pll)。151 ケースの判断基準、判断の図、覚える順、基礎知識。
  `references/article/` に、記事のデータから生成したものがある
- **計算**:megaminx-image(同梱)で、ケースの図のステッカーの色から、特徴(ペア・偽ペアなど)の位置やピースの動きを求めたもの。
  ケースごとの結果は `references/article/cases/` に書いてあり、ほかの向きや横断の質問は `scripts/` で計算する

メガミンクスの上面は五角形で、面・頂点の呼び方や、コーナーの 2 枚の組み合わせを頭の中で追うと簡単に取り違える。
**位置・色・特徴の有無・ピースの動き・確率・手順は、記憶や推測で答えず、必ず表かスクリプトで確かめてから答える。**

## どこを読むか

| 聞かれたこと                                           | 読むもの・使うもの                                                                                           |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| あるケースの見分け方・手順・特徴・動き・確率           | `references/article/stages.md` でケースの段階を引き、`references/article/cases/<段階>.md` の、そのケースの節 |
| 段階(グループ)の特徴、覚える順                         | `references/article/stages.md`                                                                               |
| 用語の意味(偽ペア、ヘッドライト、Rブロック、Yペアなど) | `references/terms.md`、記事の説明は `references/article/basics.md`                                           |
| 位置の呼び方、ステッカーの番号                         | `references/stickers.md`                                                                                     |
| 英語で答えるときの用語・位置の訳                       | `references/glossary-en.md`                                                                                  |
| 手順の記法                                             | `references/notation.md`                                                                                     |
| 確率、5 回対称、PLL の数                               | `references/article/basics.md`(豆知識の枠)。1/720 のケースだけ、cases の節にも書いてある。ほかは 1/144       |
| 「〇〇があるケースは?」「この特徴の組み合わせは何?」   | `scripts/search.mjs`、`scripts/features.mjs`                                                                 |
| 図を見せてほしい                                       | `scripts/figure.mjs`(下の「図を作る」)                                                                       |

段階のファイル名は段階の名前(`A.md`、`F2-5.md`、`K1.md` など)。ケースの節は `## A1+` のような見出しなので、見出しで探せる。

## 答え方

0. **質問と同じ言葉で答える**。英語で聞かれたら英語で答え、用語・位置の訳は `references/glossary-en.md` の表にそろえる(記事とスクリプトの出力は日本語なので、その表で訳す)。記事の文も訳して、地の文として説明する
1. **出典を答えに書かない**。このスキルを使う人は記事の読者なので、出典は知っている。
   「記事によると」「記事の〜では」「計算すると」「計算では」のような言葉を付けず、記事の判断基準も計算の結果も、地の文で自然に説明する。
   出典を聞かれたときと、覚える順の由来を聞かれたとき(さむぶろぐの「Megaminx PLL 全手順会議議事録」)だけ答える
2. **見分け方は、記事の判断基準を土台にする**。記事に書いていない判断の手がかりを、自分で作って勧めない。
   特に、偽ペア・偽ブロック・偽ヘッドライトはどのケースにもたくさんあるので、記事が使っていないものを「これで見分けられる」と言わない。
   判断基準に無いことを答えるとき(計算だけで分かる事実を言うときなど)は、見分け方の一部だと受け取られないよう、
   「判断には使わないが、〜もある」「見分けるときには見ないが、〜」のように一言断る。この断りにも「記事」という言葉は使わない
3. **記事の向きに合わせる**。記事の判断基準は「ペアを手前に置いた時」「左上と右下にヘッドライトを置いて」のように向きを決めていることが多い。
   cases の「計算」はケースの図の向き(rotate 0)なので、記事の言う向きの話をするときは `features.mjs --rotate n` で確かめてから言う
4. **相手の言うことと計算が食い違ったら**、どちらかに合わせて黙って答えず、図の色や位置の根拠を見せて指摘する
   (例:「A2+ に偽バーがある」と言われたら、「左上の面は右側だけが偽ペアで、左側は色が合っていないので偽バーではない」のように、どこがどう違うかで示す)
5. **位置の言葉を書き分ける**。「左上」は面にも頂点(コーナー)にもある。「左上の面」「左上のコーナー」のように言い分ける。
   記事の文が面か頂点かを書いていないとき(「偽ペアが左下、右下にある」など)は、計算でどちらかを確かめてから言う(訳すときも同じ)
6. **記事の数え方に合わせる**。ブロックの中のペアはペアと数えない、3x2ブロックや繋がった 2 つのバー(U)は Jブロックと呼ばない、など(`terms.md`)
7. **確率は、聞かれたときだけ答える**。ほとんどのケースは 1/144 なので、ケースの説明に毎回添えない
8. **ピースの動きは AUF を除いて言う**。「どこが動かないか」は cases の「計算:ピースの動き」の結果で言う
9. 答えは質問に合わせて簡潔に。ケースの見分け方を聞かれたら、記事の判断基準を、記事の判断の図を添えて説明する(「図を作る」)

## スクリプト

スキルのフォルダで `node scripts/<名前>.mjs` として動かす(Node.js が要る。megaminx-image は `scripts/vendor/` に同梱してあるので、インストールは要らない)。

| スクリプト                     | 何をするか                                                                                                                                |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `features.mjs <ケース...>`     | 面ごとの 3 枚の色、頂点のコーナー、見つかった特徴とその位置。`--rotate n`(向きを変える)、`--group A`、`--alg "手順"`、`--brief`           |
| `corners.mjs <ケース...>`      | AUF を打ち消したうえで、どのコーナー・エッジがどこへ動くかと、動かないピース。`--alg`、`--arrows`                                         |
| `search.mjs <特徴> --anywhere` | その特徴があるケースを全部。`--count 2` でちょうど 2 個あるケースだけ。`--where 右下` で位置を絞る(全部の向きを探す)、`--group`、`--only` |
| `figure.mjs <ケース>`          | ケースの図(SVG)。下の「図を作る」                                                                                                         |

ケース名は大文字・小文字を区別しない。ケース名が分からず手順だけ分かるときは `--alg` を使う。

コード実行が使えないときは、`references/article/cases/` の表だけで答える(ケースの図の向きの特徴と動きは書いてある)。
その場合、図を作れないことと、向きを変えた確かめはできていないことを一言だけ断る。

## 図を作る

**図で示せる答えには、聞かれなくても最初から図を付ける。**「図も作れます」「図で見たい場合は〜」のような申し出は書かない。

| 質問                                              | 付ける図                                                                                   |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| ケースの見分け方(2 つのケースの見分け方なら両方)  | 記事の判断の図(`--mark`)を、そのケースの分すべて。記事の判断の図が無いケースは、ケースの図 |
| 特徴の位置(偽ペアがどこにあるか、など)            | その特徴だけに色を残した図(`--feature`)。矢印は付けない                                    |
| ピースの動きそのもの(「コーナーがどう動く?」など) | 矢印の図(`--arrows`)                                                                       |
| 手順・確率・覚える順だけ                          | 付けない                                                                                   |

- メガミンクスの PLL は、ピースの動きを追わず、色と場所で見分けるケースが多い。記事が判断の図に矢印を付けているのは、
  動きに注目しないと見分けにくいケース(E1・E2・E3・H1±・U1±・U2±・Z1・Z2・Z3・K1±)だけ。
  見分け方の答えに、記事が使っていない動きの話や矢印を自分から足さない
- 動きを聞かれたケースが、記事で矢印を付けていないケースなら、「見分けるときに動きを追う必要はない」と一言添える
- 1 つの答えの図は 6 枚程度まで。「〇〇があるケースは?」のように件数が多い答えでは、代表的なものだけ図にする
- コード実行が使えず図を作れないときは、図なしで答え、「図はコード実行をオンにすると付けられる」と一言だけ添える

```
node scripts/figure.mjs A1+                        ケースの図(記事と同じ向き)
node scripts/figure.mjs A1+ --rotate 2             上面を時計回りに 2 回回した向き
node scripts/figure.mjs Y1+ --feature Yペア        その特徴だけに色を残す(--feature は何度でも。「偽ペア@右下」で位置を絞る)
node scripts/figure.mjs A2+ --arrows corners       揃えるとピースが行く先の矢印(corners・edges・all)
node scripts/figure.mjs S1+ --mark 1               記事の判断の図(cases の「記事の判断の図」の番号)
node scripts/figure.mjs --alg "R U R' ..."         手順で揃うケースの図
```

- 出力先は `--out` で、相手に渡すファイルを置く場所(スキルのフォルダの外)を指定する。既定では今いるフォルダに書く
- 書き出した SVG は、ファイルとして相手に渡す。表示できる場では、その SVG を見せる
- 記事の判断を説明するときは、まず記事の判断の図(`--mark`)を使う。記事の図に無いものを見せたいときだけ `--feature`・`--show` で作る
- `--feature` で、その向きに無い特徴を指定するとエラーになり、ある特徴の一覧が出る。言葉と図が食い違わないよう、その一覧で確かめる
- 矢印は「揃えるには、矢印の元にあるピースが、矢印の先の位置へ行く」ことを表す。相手にもこの言い方で説明する。AUF が要るケースは、AUF を除いた動きになるので、そう断る
- 色は既定の配色(側面はピンク・クリーム・水色・オレンジ・緑、上面は灰色)。灰色の濃いステッカーは「見なくてよいところ」
