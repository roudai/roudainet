# Megaminx PLL の判断

メガミンクスの PLL の判断の図を作り、判断の文章を確かめるためのスキル。
大事なのは、**位置・色・特徴・ピースの動きを、推測でなく計算で確かめる**こと。
メガミンクスの図は五角形で、面・頂点の呼び方や、コーナーの 2 枚の組み合わせを頭の中で追うと簡単に取り違える。
だから、言葉で言われた特徴(「左上の偽バー」など)も、書かれた文章(「バーが右上」など)も、まずスクリプトで確かめる。
食い違ったら、どちらかに合わせて黙って直さず、計算の結果を見せて相手に聞く。

## 最初に読むもの

- `references/stickers.md`:ステッカーの番号(0–25)、面・頂点の呼び方、コーナーの 2 枚、rotate と AUF、show、arrows(矢印の向きの決め方)。番号や位置を扱うなら必ず読む
- `references/terms.md`:ペア・バー・ブロック・3x2ブロック・ヘッドライト・Rブロック・Jブロック・Yペアと、その偽物の定義、show の取り方、運営者の数え方・呼び方。図を作る・文章を見るなら必ず読む
- megaminx-image の使い方(図の作り方、記法、配色、PNG の書き出しなど)は、このスキルには写していない。要るときはプロジェクトの `node_modules/megaminx-image/README.ja.md` を読む(入っている版と一致する)
- `references/roudainet.md`:roudai.net のリポジトリでの作業(どのファイルに書くか、誰が書くか、レビューの仕方、確かめ方、コミット)。そのリポジトリにいるときに読む

## スクリプト(`scripts/`)

megaminx-image(1.1.0 以上。`show` を使うため。矢印の `arrows` は 1.2.0 以上)が入っているプロジェクトで、`node <スキルのパス>/scripts/<名前>.mjs` として動かす。
node が megaminx-image を見つけられる場所(そのプロジェクトの中)で実行すること。

| スクリプト | 何をするか |
| --- | --- |
| `features.mjs <ケース...>` | 面ごとの 3 枚の色、頂点のコーナー、見つかった特徴(左右の Rブロック・Yペアを含む)と、その show の番号。ブロックの中のペアには印を付け、外のペアの数を出す。`--brief`(特徴だけ。ふだんはこれ)、`--group E`、`--rotate n`、`--json` |
| `corners.mjs <ケース...>` | AUF を打ち消したうえで、どのコーナー・エッジがどこへ動くか(巡回)と、動かないコーナー。`--arrows` で矢印の組も出す |
| `search.mjs <特徴> [--where 位置]` | その特徴が指定の位置に来るケースと rotate を探す。基礎知識の例の図を選ぶとき。`--anywhere` で位置を問わず全ケースを横断(「〜なのは X だけ」を確かめるとき)。`--only`、`--group`、`--limit`、`--with-block` |
| `shot.mjs <タブ> [--case ケース]` | roudai.net のページを確認用のサーバーから画像に撮る(サイト固有。`references/roudainet.md`) |
| `lib.mjs` | 共通の処理。別の調べ方が要るときは、これを import して小さなスクリプトを書く |

## 判断の図を作る

頼まれ方の例:「H の図を作ります。判断基準は〇〇と△△」

1. `features.mjs --brief` で、そのケース(またはグループ)の特徴を出す
2. 言われた特徴が、言われた位置に本当にあるかを確かめる。無い・別物(偽ペアと偽バーなど)なら、作る前に聞く
3. show は `terms.md` の取り方で決める。判断に使う同じ種類の特徴が複数あれば 1 枚にまとめる。ラベルは短い名詞
   - ピースの動きを矢印で見せるときは、`corners.mjs --arrows` の組を使う(向きと番号の決まりは `stickers.md` の arrows)。手で組を書かない
4. 書いたら図を目で確かめる(roudai.net なら `shot.mjs`)
5. 作った図を、ケースごとに「何を見せたか(番号と位置)」と短く報告する

## 判断の文章をレビューする

頼まれ方の例:「E を書いたのでレビューして」

1. 文章の主張(位置、色、どのコーナーが入れ替わるか、どこが動かないか、AUF)を一つずつ取り出す
2. `features.mjs` と `corners.mjs` で確かめる。必要なら `--rotate` で文章の言う向きにして確かめる
3. 指摘を「誤り」と「提案」に分け、番号を振り、根拠(計算の結果)を添える。おすすめの直し方があればそう書く
4. 用語の使い方が `terms.md` の定義とそろっているかも見る
5. 直すのは、相手が選んだものだけ。文章を書き換える案は出すが、勝手に書き直さない(文章は書き手のもの)

## 気をつけること

- 相手が独自の言葉(「Yペア」「続くペア」など)を使い、意味がはっきりしないときは、図を作る前に確かめる。推測で塗ると、作り直しになる
- 「左上」は面にも頂点にもある。どちらの意味かを文章で取り違えていないか、自分の説明でも書き分ける
- rotate を変えた図の番号は、回した後の位置で数える
- 3x2ブロックの中のバーやブロックは、それぞれ別にも出てくる(`features.mjs` は重なりを省かない)。判断に使うのはどれかを考えて選ぶ
- ピースの動きは AUF のずれで見かけが変わる。「どこが動かないか」は `corners.mjs` の結果で言う
- 調べるための一時的なスクリプトや画像は、リポジトリの外(一時フォルダなど)に置く。リポジトリの中に置くと、消し忘れたときに作業中の変更に混ざる。
  ただし megaminx-image を import するスクリプトは、node がそれを見つけられるよう、`lib.mjs` を絶対パスで import するか、プロジェクトの `node_modules` が見える場所で動かす
