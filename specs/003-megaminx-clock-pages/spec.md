# Feature Specification: Megaminx、Clock、Other のページの移植

**Feature Branch**: `003-megaminx-clock-pages`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "Megaminx と Clock の解法ページ(megaminx 4ページ、clock 1ページの計5ページ)を、legacy/pages/ から新サイト(Nuxt 4 + TypeScript、静的生成のみ)へ移植する。対象は /megaminx/megaminx-eo、/megaminx/megaminx-co、/megaminx/megaminx-ep、/megaminx/megaminx-cp、/clock/clock-no-flip。現行サイトと同じ URL、内容、見た目、挙動を再現する(パリティ優先、原則 IV。明らかな誤字は例外として直し記録する)。megaminx の図は現行どおり sr-puzzlegen で描画しており、原則 VIII により spike で検証する。002 で作った仕組み(CubeImage と同様の図のコンポーネント、Bulma のクラスの再現、verify-output と verify-parity、scripts/pages.mjs)を再利用する。legacy/components/MegaminxView.vue と legacy/assets/images/megaminx/ の画像は、現行のどのページからも使われておらず配信もされていないため対象外とする。other とトップページは別の Spec で扱う。"

**入力の訂正(2026-11-19)**: 入力では `legacy/components/MegaminxView.vue` を対象外としていたが、megaminx の 4 ページは `<megaminx-view>` としてこのコンポーネントを使っている(調査時に、ケバブケースの表記を見落としていた)。そのため、MegaminxView の表示(図と手順の 1 行)は移植の対象に含める。`legacy/assets/images/megaminx/` の画像 16 枚は、移植元のソースにも本番の HTML にも参照がなく、対象外のままとする。

**範囲の追加(2026-11-19)**: 運営者の指示により、入力では別の Spec としていた Other の 3 ページ(`/other/3x3x3-method`、`/other/for-non-cubers`、`/other/advent-calendar2014`)も、この Spec に含める。3 ページとも文章とリンクだけで、図や画像はない。ブランチ名とディレクトリ名(`003-megaminx-clock-pages`)は、作成済みのため変えない。トップページは、引き続き別の Spec で扱う。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Megaminx の手順ページで、図と手順を見比べられる (Priority: P1)

訪問者は、Megaminx の EO、CO、EP、CP の各ページを開き、ケースごとに、Megaminx の上面の状態を示す図と、その手順を並べて見ることができる。見出し、ケースの並び、図の見た目は、現行サイトと同じである。

**Why this priority**: この Spec のページの大半(4 ページ、46 ケース)を占める。図を描く手段(原則 VIII の spike の対象)もここで決まる。

**Independent Test**: `/megaminx/megaminx-eo`、`/megaminx/megaminx-co`、`/megaminx/megaminx-ep`、`/megaminx/megaminx-cp` を開き、見出し、図、手順の文字列が、現行サイトと同じ数、順序、内容で表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 訪問者が Megaminx のページを開いている、**When** ページを下までスクロールする、**Then** 現行と同じ見出し(「2つ反転」など)の下に、同じケースが、同じ図と手順の文字列で、同じ順序に並んでいる。
2. **Given** 訪問者が Megaminx のページを開いている、**When** 各ケースの図を見る、**Then** 図は、現行サイトと同じ視点、配色、マスク、矢印で、そのケースの状態を示している。
3. **Given** 訪問者がモバイル幅で Megaminx のページを開いている、**When** ケースを見る、**Then** 図と手順が現行サイトと同じく横に並び、手順の文字列が読める。
4. **Given** 訪問者が静的に生成されたページを開いた、**When** 図の表示が終わる、**Then** すべてのケースに図が表示され、空欄の図が0件である。

---

### User Story 2 - Clock と Other の文章のページを読める (Priority: P2)

訪問者は、ルービッククロックの No-Flip Method のページと、Other の 3 ページ(各種解法、知っておいてほしいこと、続ける意味について)を開き、本文、見出し、外部へのリンクを、現行サイトと同じ内容で読むことができる。

**Why this priority**: 4 ページとも文章とリンクだけで、図はない。パリティの対象だが、図の描画を伴う US1 より移植の難しさが小さい。

**Independent Test**: `/clock/clock-no-flip`、`/other/3x3x3-method`、`/other/for-non-cubers`、`/other/advent-calendar2014` を開き、見出し、本文、リンクが、現行サイトと同じ内容と順序で表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 訪問者が `/clock/clock-no-flip` を開いている、**When** ページを読む、**Then** 現行と同じ見出し(「1. エッジ記憶」〜「ヒント」)と本文が、同じ順序で表示される。
2. **Given** 訪問者が `/other/3x3x3-method` を開いている、**When** ページを読む、**Then** 現行と同じ解法の見出し(リンク付き)と手順の番号付きリストが、同じ順序で表示される。
3. **Given** 訪問者が `/other/for-non-cubers` または `/other/advent-calendar2014` を開いている、**When** ページを読む、**Then** 現行と同じ見出しと本文が、同じ順序で表示される。
4. **Given** 訪問者が本文の外部リンクを選ぶ、**When** リンクを開く、**Then** 現行サイトと同じ URL へ移動する(4 ページで計 21 本)。

---

### User Story 3 - メニューから全ページへ移動でき、404 にならない (Priority: P2)

訪問者は、ヘッダーの Megaminx、Clock、Other のメニューにある内部ページの全項目から、対応するページへ移動できる。現行サイトと同じ URL で直接開いても、同じページが表示される。

**Why this priority**: 現時点で、これらのメニュー項目は 404 になっている。URL の互換性(原則 II)を、この範囲で満たす。

**Independent Test**: 静的生成の出力に、対象の 8 パスがすべて含まれていることを確認し、各メニュー項目を選んでページが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 訪問者が任意のページを開いている、**When** Megaminx、Clock、Other のメニューの内部ページの項目を選ぶ、**Then** 対応するページが、共通のヘッダーとフッターとともに表示される。
2. **Given** 訪問者が対象の 8 パスのいずれかを、ブラウザーで直接開く、**When** ページを読み込む、**Then** 404 にならず、そのページが表示される。

---

### User Story 4 - 運営者が、直した誤字を確認できる (Priority: P3)

運営者は、移植の際に直した明らかな誤字・誤記と、直さなかった候補の一覧を、Spec の文書で確認できる。

**Why this priority**: 原則 IV の例外の運用に必要な記録である。

**Independent Test**: 修正の記録の各行について、新サイトが修正後の表記になっていること、記録にない差分が現行サイトとの間にないことを確認する。

**Acceptance Scenarios**:

1. **Given** 移植の際に誤字を直した、**When** 運営者が修正の記録を見る、**Then** ページ、場所、現行の表記、修正後の表記、理由が記録されている。
2. **Given** 誤字かどうか判断に迷う表記がある、**When** 移植する、**Then** 現行の表記のまま残し、修正の候補として記録する。

---

### Edge Cases

- 図の表示にスクリプトが必要な場合: スクリプトが動く前(静的生成された直後の HTML)でも、見出しと手順の文字列は読める。図は、スクリプトの実行後に表示される。
- 図の描画に失敗した場合: そのケースの図の領域が空になっても、手順の文字列と他のケースの表示は崩れない。
- 同じページに多数の図がある場合(CO の 16 ケースなど): すべての図が表示され、現行サイトと比べて、運営者がスクロールや操作を体感で遅いと感じない。
- 狭い画面で、長い手順の文字列がある場合: 現行サイトと同じ折り返しになり、ページ全体が横にはみ出さない。
- 外部リンクの先が既に存在しない場合: リンク先は現行のまま残す。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: サイトは、次の 8 パスのページを、現行サイトと同じパスで提供しなければならない(MUST)。`/megaminx/megaminx-eo`、`/megaminx/megaminx-co`、`/megaminx/megaminx-ep`、`/megaminx/megaminx-cp`、`/clock/clock-no-flip`、`/other/3x3x3-method`、`/other/for-non-cubers`、`/other/advent-calendar2014`。
- **FR-002**: 各ページの見出し、本文、手順の文字列、リンクは、現行サイト(`legacy/pages/` の対応するファイル)と同じ内容と順序でなければならない(MUST)。ただし、FR-007 で記録した誤字の修正は除く。
- **FR-003**: Megaminx の図は、現行サイトと同じケースに対して、同じ視点、配色、マスク、矢印で表示しなければならない(MUST)。
- **FR-004**: 各ページは、共通のヘッダーとフッターの中に表示しなければならない(MUST)。
- **FR-005**: 各ページの見た目(レイアウト、余白、図と手順の並び、モバイル幅での表示)は、現行サイトと同等でなければならない(MUST)。デザインの刷新や機能の追加を行ってはならない(MUST NOT)。
- **FR-006**: 外部へのリンクは、現行サイトと同じ URL でなければならない(MUST)。
- **FR-007**: 移植の際に明らかな誤字・誤記を直した場合は、ページ、場所、現行の表記、修正後の表記、理由を、この Spec の文書に記録しなければならない(MUST)。判断に迷う表記は、直さずに候補として記録する。
- **FR-008**: ページの見出し、本文、手順の文字列は、静的生成した HTML に含まれていなければならない(MUST)。図だけは、ブラウザーでの描画に頼ってよい。
- **FR-009**: サイトは、引き続き静的生成のみで出力しなければならない(MUST)。
- **FR-010**: Megaminx の図を描く外部ライブラリは、採用前に、開発サーバーと静的生成の出力の両方で動くことを spike で検証しなければならない(MUST、原則 VIII)。
- **FR-011**: トップページの中身は、この Spec の対象外とする。Other のメニューのうち外部サイト(ルービックキューブの世界、ブログ版ろーだいねっと)への項目は、001 で実装済みのため、変更しない。
- **FR-012**: `legacy/` 配下のファイルを変更してはならない(MUST NOT)。

### Key Entities *(include if feature involves data)*

- **解法ページ**: 8 つのページそれぞれ。パス、見出し、本文、ケースを持つ。移植元は `legacy/pages/` の対応するファイルである。
- **Megaminx のケース**: 図(上面の状態を示す)と、手順の文字列を持つ。移植元では、`MegaminxView` コンポーネントが、図と手順の 1 行を横に並べて表示している。
- **誤字の修正の記録**: 直した、または直す候補とした表記の一覧。ページ、場所、現行の表記、修正後の表記、理由を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 対象の 8 パスのすべてが、静的生成の出力に含まれ、メニューと直接のアクセスの両方で表示される。404 は0件である。
- **SC-002**: 各ページの見出し、手順の文字列、本文が、現行サイトと比べて、記録した誤字の修正を除き、不足や相違が0件である。
- **SC-003**: Megaminx のページで、図が表示されないケースが0件である(4 ページ、計 46 ケース)。
- **SC-004**: 運営者が、狭い画面と広い画面の両方で、各ページを現行サイトと並べて比較したとき、レイアウトと図の表示に、気づく相違がない。
- **SC-005**: 外部リンクのすべてが、現行サイトと同じ URL を指している。相違は0件である。
- **SC-006**: 移植で直した誤字のすべてが記録されており、記録にない表記の変更が0件である。
- **SC-007**: Lint、型チェック、静的生成、出力の検証が、すべて成功する。

## Assumptions

- 内容の正は `legacy/pages/` の各ファイルとする。現行の本番サイトとの比較は、002 で作った確認の仕組み(本文の比較のスクリプトと、スクリーンショットの比較)で行う。
- 図を描く手段(現行と同じ `sr-puzzlegen` を使うか、代替にするか)は、この Spec では決めず、Plan で spike の結果をもとに決める(原則 VIII)。
- `legacy/assets/images/megaminx/` の画像 16 枚は、移植元のどのページからも参照されておらず、本番サイトでも配信されていないため、対象外とする(Constitution の「解法画像を引き継ぐ」は、配信されている画像を対象とすると解釈する)。
- 現行のページには、ページごとのタイトルや meta タグがない。この Spec でも追加しない。
- 誤字の候補の例として挙げていた `/clock/clock-no-flip` の「4つの覚えるべき数字かできます」は、移植の際に「数字ができます」に直し、下の表に記録した(FR-007)。
- テストコードは、この Spec では必須としない。ただし、Lint と型チェックは必須である(原則 V)。
