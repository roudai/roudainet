# Data Model: トップページの移植と情報の更新

**Feature**: `004-top-page` | **Date**: 2026-11-19

トップページは、テンプレートに本文を直接書く(research.md の 4)。コードで持つデータはない。
文書で管理するデータは、更新と修正の記録だけである。

## InformationUpdate(情報の更新と修正の記録)

spec.md の「現行の内容から更新した箇所」の表の1行。002 と 003 の TypoCorrection と同じ表で、Constitution 1.2.0 の原則 IV の2つの例外(誤字の修正、古くなった情報の更新)の両方を記録する。`scripts/verify-parity.mjs` が読み、差分の例外として扱う。

| フィールド | 説明 |
|---|---|
| ページ | 対象のパス(`/`) |
| 場所 | ページの中の位置 |
| 現行の表記 | 移植元のテキスト。リンクを含む場合は `テキスト(\`URL\`)` の形 |
| 修正後の表記 | 新サイトのテキスト。リンクを含む場合は `テキスト(\`URL\`)` の形。追加の場合は、直前の項目のテキストに、追加分を続けたもの |
| 理由 | 更新の理由と、出典(URL と確認日)。直さない候補は「候補(直さない)」 |

**検証ルール**:

- 「現行の表記」のテキストは、本番の現行サイトの本文に含まれていなければならない(含まれない場合、`verify-parity.mjs` は失敗する)。
- 情報の更新の行は、理由に出典の URL と確認日を含まなければならない(Constitution 1.2.0)。
