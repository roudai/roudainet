# Research: トップページの移植と情報の更新

**Feature**: `004-top-page` | **Date**: 2026-11-19

Plan の Technical Context で未確定だった項目を調べた結果をまとめる。新しい依存ライブラリはないため、spike(原則 VIII)は不要である。

## 1. 更新する情報の確認(出典)

- **Decision**: spec.md の「現行の内容から更新した箇所」の値を、次の出典で確認した値に固定する。ページには、確認した時点の値を静的に書く。
  - WCA の公開 API `https://www.worldcubeassociation.org/api/v0/persons/2009ISHI01`(2026-11-19): 平均の自己ベストは、3x3x3 13.02、3x3x3 Fewest Moves 32.00、4x4x4 43.15、5x5x5 1:32.83、Megaminx 1:02.42、Pyraminx 6.26、Clock 8.98、Skewb 7.98。現行のページと異なるのは Megaminx だけ。
  - 同 `/results`(2026-11-19): 決勝の表彰台は 11 回で、最新は 2016 年。アジア大会と日本大会の表彰台は、現行の「主な成績」の 4 件と一致する。
  - `https://wca-seniors.org/data/Senior_Rankings.js`(2026-11-18 02:07 更新): 40 歳以上の Megaminx で、単発 52.87(318 人中 2 位)、平均 1:02.42(206 人中 2 位)。いずれも Ota Spring 2025 の記録。
  - `https://select.tribox.com/pages/start`(2026-11-19、200): ページ名は「はじめてのスピードキューブ – tribox SELECT」。
  - `https://github.com/roudai/roudainet/issues`(2026-11-19、200)。現行の `https://github.com/roudai/roudai.net/issues` は 404。
- **Rationale**: WCA の個人ページは、ブラウザーでの描画が必要な部分があるため、同じデータを返す公開 API で確認した。Senior Rankings のページも、表をスクリプトで描画するため、元のデータファイルで確認した。
- **Alternatives considered**: ビルド時や表示時に、WCA や Senior Rankings から最新の値を取得する。常に最新になるが、機能の追加にあたり(原則 IV の例外の対象外)、外部サービスへの依存も増えるため採用しない。

## 2. シニアランキングの表示

- **Decision**: 「主な成績」の後に、見出し「シニアランキング（40歳以上、2026年11月時点）」と、次の 2 項目のリストを置く。順位の部分を、出典の該当箇所へのリンクにする。
  - `Megaminx 単発 52.87 世界2位`(「世界2位」が `https://wca-seniors.org/Senior_Rankings.html#minx` へのリンク)
  - `Megaminx 平均 1:02.42 世界2位`(「世界2位」が `https://wca-seniors.org/Senior_Rankings.html#minx-average` へのリンク)
- **Rationale**:
  - 既存の「主な公式記録（平均）」(`Megaminx 1:02.42` の形)と「主な成績」(`… 3位` の形)の書き方に揃え、見出しと括弧は現行と同じ全角にする。
  - 順位は今後変わるため、見出しに確認した時点を入れる(spec.md の Edge Cases)。
  - 見出しとリストだけで構成し、新しいスタイルや部品を作らない(デザインの刷新にあたらない)。
- **Alternatives considered**: 「主な成績」のリストに 2 項目を足す。見出しが増えないが、「主な成績」は大会の表彰台の一覧で、性質が異なるため採用しない。
- **確認**: 文言は、実装後に運営者が確認する(spec.md の Assumptions)。

## 3. パリティの確認の拡張

- **Decision**: 002 の `scripts/verify-parity.mjs` を、次の 3 点で拡張して、トップページにも使う。
  1. パス `/` のとき、現行サイトの URL を `https://roudai.net/` にする(現在は `${origin}${page}/` のため `//` になる)。
  2. spec.md の表のセルが `テキスト(\`URL\`)` の形のとき、テキストとリンク先を分けて読む。テキストは従来どおり置き換え、リンク先は、現行のリンクの一覧の中で置き換える。
  3. 「現行の表記」に URL がなく、「修正後の表記」に URL がある行は、追加されたリンクとして、現行のリンクの一覧の末尾に足す(追加がページの最後にある場合だけ正しい。この Spec の追加は最後にある)。
- **Rationale**: 更新の記録(spec.md の表)と、実際の差分が一致することを機械的に確かめられる(SC-002、SC-003、SC-004)。既存の 21 ページの表には URL のセルがないため、既存の動作は変わらない。
- **追加の記録の書き方**: シニアランキングの追加は、spec.md の表で、「現行の表記」を直前の項目(`日本大会2016 最少手数3位`)、「修正後の表記」をその項目に追加分のテキストを続けたものにする。テキストの置き換えで、追加の位置も確かめられる。
- **Alternatives considered**: トップページだけ目視で確認する。1 ページで量は少ないが、記録にない変更が0件であること(SC-003)を確実にするため、スクリプトで確かめる。

## 4. ページの構成

- **Decision**: `app/pages/index.vue` を、移植元 `legacy/pages/index.vue` のテンプレートで置き換え、spec.md の表の更新を反映する。スクリプトとデータは持たない。`scripts/pages.mjs` に `/` を追加する。
- **Rationale**: 本文、リスト、リンクだけのページで、002 と 003 の文章のページと同じ扱いで足りる。`<h1>` と `<br />` を使うが、001 の `.content` のスタイルで表示できる(`h1` のスタイルがあることは確認する)。
