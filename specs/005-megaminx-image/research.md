# Research: Megaminx の図を自作ライブラリで描く

**Feature**: `005-megaminx-image` | **Date**: 2026-11-24

調べた手順のスクリプトと画像は、リポジトリの外(作業用のフォルダー)で作り、コミットしていない。結果だけをここに記録する。

## 1. 今の図とライブラリの図で、ステッカーの面が一致するか

- **Decision**:図の手順(`case`)は、今のデータの値をそのまま使う。変換(逆にする、`y` を消すなど)は要らない。
- **Rationale**:
  - `sr-puzzlegen` 1.0.4 の `Visualizer` を、描画器だけを差し替えて Node で動かし、`megaminx-top` の 26 枚の位置と色を取り出した。megaminx-image 1.0.0 の `stickerColors()` の 26 枚と、画面上の位置(上面の中心からの角度の順。F が下)で対応を付けて比べた。
  - 揃った状態で、側面の並び(BL、L、F、R、BR)が両者で一致することを確かめてから比べた。
  - **46 個すべてで、26 枚の色(今の配色を与えたとき)と、26 枚の面(ライブラリの既定の配色を与えたとき)が一致した**。
  - 比べ方の確認:`rotate: 1`(U を 1 回ずらす)にすると、CP と EP の 27 個中 0 個が一致する。手順を `alg`(逆にしない)として渡すと、27 個中 7 個(手順が自身の逆と同じ状態になるケース)だけが一致する。
  - 手順には、括弧(`(R U R' U2')` など)と、前置きの `(U)`・`(U')` が含まれる。図の手順に `y` を含むものは無い(`y` は、表示用の `megacase_view` にだけある)。
  - 46 個すべてを、今の図(矢印つき)とライブラリの図で並べた画像を作り、目で見ても同じ配置であることを確かめた。
- **Alternatives considered**:手順を `alg` に変換して渡す。一致しないケースがあるため、採らない。

## 2. 図の指定のデータの形

- **Decision**:データを、ライブラリの形に合わせた `{ case: string; oll?: true }` に書き換える。変換の層ははさまない(data-model.md)。
- **Rationale**:
  - 今の指定は 2 種類しかない。
    - 配色の指定がある 27 個(CP 15、EP 12):配色はすべて同じで、矢印(`arrows`)がある。
    - マスクの指定がある 19 個(CO 16、EO 3):マスクはすべて「U 以外の 11 面の全ステッカー」で、OLL の図と同じ意味である。
  - 配色はライブラリの既定に合わせると決めた(spec の FR-004、FR-005)。そのため、配色もマスクも、「OLL 型かどうか」の 1 つの区別で表せる。
  - 変換の層をはさむと、使わない値(`arrows`、色の `name`、`width`、`height`)と、マスクの変換を残し続けることになる。データは 2,300 行ほどから、200 行ほどになる見込み。
- **Alternatives considered**:
  - 今のデータを残し、部品の中で変換する。使わない値が残り、`sr-puzzlegen` の型にも頼り続けるため採らない。
  - ライブラリの `StateOptions` をそのまま持つ(`scheme: ollScheme()` を各データに書く)。46 個に同じ値を書くことになり、配色を部品の 1 か所で決められなくなるため採らない。

## 3. 描き方:静的生成のときに SVG を HTML に含める

- **Decision**:`MegaminxImage.vue` で、ライブラリの `svg()` を `computed` で呼び、描画先の div に `v-html` で入れる。サーバー側(prerender)とブラウザーの両方で同じ関数を呼ぶ。
- **Rationale**:
  - ライブラリの `svg()` は、同じ入力からどの環境でも同じ文字列を返す(ライブラリの契約)。そのため、ハイドレーションで食い違いが起きない。
  - spike(下の 4)で、開発サーバーでも、生成した出力でも、ハイドレーションの警告が出ないことを確かめた。
  - スクリプトが無効でも図が表示され、図が後から現れてレイアウトが動くこともない(FR-002)。
  - 大きさ(spike の出力、圧縮前 → gzip 後):
    - HTML は 1 ページあたり、圧縮前で約 8〜40KB 増えるが、gzip 後は約 0.8〜1.8KB の増加にとどまる(図の形が同じで、色だけが違うため)。
    - ブラウザーの JS:`sr-puzzlegen` のチャンク(67.9KB、gzip 17.3KB)が無くなり、megaminx-image のチャンク(11.1KB、gzip 4.9KB)が入る(SC-006)。
  - ビルドの時間:prerender の時間はほぼ変わらない(46 ルートで約 1.2 秒)。
- **Alternatives considered**:
  - ブラウザーでだけ描く(今と同じ。`drawCanvas` か `svg()` を `onMounted` で呼ぶ)。スクリプトが無いと図が出ず、レイアウトが動くため採らない。
  - SVG の文字列を、ビルドのときに作って別のファイル(JS のデータや `public/` の画像)にする。JS のデータにすると、ライブラリより大きい文字列(46 枚で約 120KB)を配ることになる。`<img>` の画像にすると、パリティの確認の画像の比較に影響し、ファイルの管理も増えるため採らない。
  - Nuxt のサーバー部品(`.server.vue`、islands)。静的生成ではアイランドの取得先が無く、実験的な機能でもあるため採らない。

## 4. spike(原則 VIII)

- **Decision**:megaminx-image 1.0.0 を採用する。
- **Rationale**:作業用の worktree で、`pnpm add megaminx-image@1.0.0` し、`MegaminxImage.vue` を上の 3 の形に置き換えて試した(2026-11-24)。
  - `nuxt generate`:成功。4 ページの HTML に、SVG が CP 15、CO 16、EP 12、EO 3(計 46)含まれた。出力に `sr-puzzlegen` のチャンクは無い(import が無くなったため)。
  - `nuxt dev` と、生成した出力(`scripts/preview.mjs`):Playwright の Chromium で、スクリプトの有効と無効の両方で 4 ページを開き、幅 100px の SVG が 46 個すべて表示されることを確かめた。コンソールの警告とエラーは 0 件(開発サーバーのハイドレーションの不一致の警告も無し)。
  - `nuxt typecheck`、`scripts/verify-output.mjs`:成功。
  - ESLint:`vue/no-v-html` の警告が 1 件出る(エラーではない)。下の 6 で扱う。
  - Node:ライブラリは Node 22.12 以上を求める。サイトは Node 24 で、条件を満たす。ESM のみのパッケージで、Nuxt(Vite)からそのまま読める。
- **Alternatives considered**:無し(運営者の指定)。

## 5. パリティの確認(`scripts/verify-parity.mjs`)

- **Decision**:図の要素の数え方を、「id を持ち、中身が空か、SVG 1 つだけの div」に広げる。
- **Rationale**:
  - 今のスクリプトは、図を「id を持つ空の div」で数える。SVG を入れると新サイトの側が 0 になり、「図の要素の数が違います(現行 15、新 0)」と失敗することを、spike で確かめた。
  - 本番の現行サイト(003 と 004 を公開した新サイト)では、図は id を持つ空の div である。数え方を広げると、本番(空)と新(SVG 入り)の両方が数えられ、図の数を正しく比べられる(FR-011)。この Spec を公開した後(本番も SVG 入り)も、同じ数え方で比べられる。
  - SVG には文字が無いため、本文のテキストの比較には影響しない。`<img>` ではないため、画像の比較にも影響しない。
  - spike で数え方を広げて実行し、Megaminx の 4 ページのうち CO、EP、EO は差分 0 件、キューブ系(`/pll/pll`、`/oll/oll`)も差分 0 件であることを確かめた。
  - 図の見た目の変化(配色、矢印)は、このスクリプトでは比べていない(図はもともと画像として比べられない)。spec.md の「現行の内容から変更した箇所」に記録し、quickstart の目視で確かめる。
- **Alternatives considered**:
  - Megaminx の 4 ページだけ、図の数の比較を例外にする。比較が弱くなるため採らない。
  - spec.md の表を読んで、図の変更を例外として扱う仕組みを足す。図の数は変わらないため、要らない。

### 既にある問題(この Spec の対象外)

- `/megaminx/megaminx-cp` では、main のままでも、`verify-parity.mjs` が「記録された修正の現行の表記「並行交換(1)」が、現行サイトに見つかりません」など 3 件の差分を出す。003 の誤字の修正の記録は、本番が移植元(Nuxt 2)だった時点を前提にしているが、本番はすでに直した表記の新サイトになっているためである。
- この Spec の変更とは関係が無いため、ここでは直さない。quickstart では、この 3 件を既知の差分として扱う。直すかどうかは、運営者が別に判断する。

## 6. `v-html` の lint の警告

- **Decision**:`MegaminxImage.vue` の `v-html` の行に、`vue/no-v-html` を無効にするコメントを付け、理由(中身はライブラリが作る SVG で、入力はサイトのデータの手順だけであり、訪問者の入力を含まない)を書く。
- **Rationale**:警告を残すと、lint の出力に毎回出る。理由をその場に残せば、後から読んでも判断が分かる。
- **Alternatives considered**:SVG を文字列ではなく Vue の要素(`<polygon>` の並び)として組み立てる。ライブラリの `svg()` の結果と同じであることを、別に保証しなければならなくなるため採らない。

## 7. 依存の整理

- **Decision**:`sr-puzzlegen` を `dependencies` から外し、`megaminx-image` を `1.0.0` に固定して加える(既存の依存と同じく、版を固定する書き方)。`sr-visualizer` は残す。
- **Rationale**:
  - `sr-puzzlegen` を使っているのは、`app/components/MegaminxImage.vue` と `app/data/megaminx/types.ts` だけである。
  - `sr-visualizer` は、キューブの図(`app/components/CubeImage.vue`、`app/data/cube/types.ts`)で使っている。
  - megaminx-image の任意の依存(`@resvg/resvg-js`、PNG の出力用)は使わないため、入れない。
- **Alternatives considered**:無し。
