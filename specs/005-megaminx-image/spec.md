# Feature Specification: Megaminx の図を自作ライブラリで描く

**Feature Branch**: `005-megaminx-image`

**Created**: 2026-11-24

**Status**: Draft

**Input**: User description: "Megaminx のページ(/megaminx/megaminx-cp、-co、-ep、-eo の 4 ページ、計 46 個の図)の図の描画を、sr-puzzlegen から、運営者の自作ライブラリ megaminx-image@1.0.0(npm 公開済み、GitHub: roudai/megaminx-image)に置き換える。003-megaminx-clock-pages で移植元と同じにした図の見た目(FR-003:同じ視点・配色・マスク・矢印)を、意図して変える機能である(Constitution 原則 IV:パリティ確認後の別の Spec)。決定事項:(1) 図は nuxt generate のときに SVG を HTML に埋め込み、JavaScript が無くても図が表示されるようにする(ライブラリの svg() は環境によらず同じ文字列を返す)。(2) 4 ページ・46 個を一度に入れ替え、sr-puzzlegen を依存から外す。sr-visualizer はキューブの図で使っているので残す。(3) 配色はライブラリの既定に合わせる:cp・ep(現在は白い上面の配色と矢印)はライブラリの既定の配色 DEFAULT_SCHEME(上面は薄い灰色)、co・eo(現在は U 以外の全面をマスク)は ollScheme() の既定(上面は薄い灰色、ほかは濃い灰色)。(4) 矢印は描かない。データからも arrows を消す。(5) 図の大きさは size 100(今の見た目の大きさとほぼ同じ)。(6) 図の指定のデータ(app/data/megaminx/types.ts と cp・co・ep・eo.ts)は、ライブラリのオプションの形(case と、OLL 型かどうか)に書き換える。事前の調査で、46 個すべてで、同じ case から作った図の各ステッカーの面がいまの図と一致することを確かめた(手順の解釈は同じ)。scripts/verify-parity.mjs は図の要素を「id を持つ空の div」で数えているため、SVG を埋めると本番(現行)との比較で数が合わなくなる。この扱い(数え方の変更、または記録した例外)も対象に含める。原則 VIII により、megaminx-image を開発サーバーと nuxt generate の出力の両方で spike して検証する。"

**003 との関係**: この Spec は、003-megaminx-clock-pages の FR-003(Megaminx の図を、現行サイトと同じ視点、配色、マスク、矢印で表示する)を、Megaminx の 4 ページについて置き換える。Constitution の原則 IV により、見た目の変更は、パリティを確認したあとの別の Spec で行う。003 は公開済み(パリティ確認済み)である。図以外(見出し、本文、手順の文字列、レイアウト)は、003 のまま変えない。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 図がページと同時に表示される (Priority: P1)

訪問者は、Megaminx の CP、CO、EP、EO の各ページを開くと、ページの文字と同時に、すべてのケースの図を見ることができる。図が後から現れて、手順の文字列の位置がずれることはない。ブラウザーでスクリプトが動かない環境でも、図は表示される。

**Why this priority**: 図の描き方を、ブラウザーでの描画から、静的生成した HTML に含める形に変えることが、この機能の中心である。表示の速さと、スクリプトが無いときの表示が良くなる。

**Independent Test**: 静的生成した 4 ページを、スクリプトを無効にしたブラウザーで開き、46 個すべての図が表示されることを確かめる。また、スクリプトが有効な状態で開き、図が表示された後に手順の文字列の位置が動かないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 訪問者がスクリプトを無効にしている、**When** Megaminx のページを開く、**Then** すべてのケースの図が表示されている。
2. **Given** 訪問者がスクリプトを有効にしている、**When** Megaminx のページを開く、**Then** 図は最初の表示から存在し、後から図が現れてレイアウトが動くことがない。
3. **Given** 静的生成した HTML、**When** 運営者が中身を確かめる、**Then** 46 個の図が、それぞれのケースの位置に、画像として含まれている。

---

### User Story 2 - 図がライブラリの見た目で、同じケースを示す (Priority: P1)

訪問者は、各ケースの図で、そのケースの上面の状態を、運営者のライブラリと同じ見た目(配色、線、形)で見る。CP と EP の図は、ライブラリの既定の配色(上面は薄い灰色)で、ステッカーの色からどこが入れ替わるかを読み取る。CO と EO の図は、上面の色(薄い灰色)とそれ以外(濃い灰色)だけで、向きを示す。矢印は描かれない。

**Why this priority**: 図の見た目を、運営者のライブラリ(と、その元のサイト)に揃えることが、置き換えの目的である。図が示すケース(どのステッカーがどの面の色か)は、今と同じでなければならない。

**Independent Test**: 46 個の図それぞれについて、今の図とステッカーごとの面を比べ、すべて一致することを確かめる。あわせて、配色、矢印の有無、図の大きさを目で確かめる。

**Acceptance Scenarios**:

1. **Given** CP または EP のページ、**When** 訪問者が図を見る、**Then** 図はライブラリの既定の配色で、今の図と同じ位置に同じ面の色があり、矢印は無い。
2. **Given** CO または EO のページ、**When** 訪問者が図を見る、**Then** 上面の色のステッカーは薄い灰色、それ以外は濃い灰色で、今の図で上面の色(白)だった位置と、薄い灰色の位置が一致する。
3. **Given** どのページでも、**When** 訪問者が図の大きさを見る、**Then** 図は今と同じ欄に、今とほぼ同じ大きさ(幅約 100px の範囲)で表示され、手順の文字列との並びは変わらない。

---

### User Story 3 - 運営者が変更を確かめ、使わないライブラリを外せる (Priority: P2)

運営者は、図以外の本文が本番サイトと変わっていないことを、これまでどおり本文の比較の仕組みで確かめられる。また、使わなくなった描画のライブラリ(sr-puzzlegen)を依存から外し、図の指定のデータを、新しいライブラリの指定の形で簡潔に保てる。

**Why this priority**: 置き換えの安全性(図以外の本文が変わらないこと)の確認と、保守のしやすさのため。訪問者に見える変化は US1、US2 で決まるので、優先度は一つ下げる。

**Independent Test**: 静的生成の後に本文の比較の仕組みを実行し、4 ページで、図に関する記録した違い以外の差分が無いことを確かめる。依存の一覧に sr-puzzlegen が無く、キューブの図が引き続き表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 静的生成した出力、**When** 運営者が本文の比較を実行する、**Then** Megaminx の 4 ページで、本文のテキスト、リンク、画像の差分は 0 件で、図の要素は数がそろっていると判定される。
2. **Given** 依存の一覧、**When** 運営者が確かめる、**Then** sr-puzzlegen は含まれず、sr-visualizer は含まれている。キューブ系のページの図は、今までどおり表示される。
3. **Given** 図の指定のデータ、**When** 運営者が読む、**Then** 各図は、ケースの手順と、OLL 型(上面の色だけを示す図)かどうかだけで指定されており、矢印、マスク、使わない色の名前、幅と高さの値は含まれていない。

---

### Edge Cases

- 図の手順が読めない(記法の誤りなど)場合: 静的生成の時点でエラーとして気づける。誤った図や空の図のまま公開されない。
- 図の手順に、持ち替え(`y`)や括弧、`(U')` のような前置きの U が含まれる場合: 今の図と同じケースとして描かれる(事前の調査で、46 個とも一致を確認済み)。
- 狭い画面の場合: 図と手順の文字列は、今と同じく横に並び、図の大きさは変わらない。ページ全体が横にはみ出さない。
- ダークモードなど、背景の色が変わる環境: サイトは今もダークモードに対応していないため、考慮しない。図の背景は透明のままとする。
- 同じページに多数の図がある場合(CO の 16 ケースなど): HTML が大きくなっても、運営者が体感で表示が遅いと感じない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Megaminx の 4 ページ(`/megaminx/megaminx-cp`、`/megaminx/megaminx-co`、`/megaminx/megaminx-ep`、`/megaminx/megaminx-eo`)の 46 個の図は、運営者のライブラリ megaminx-image(1.0.0)で描かなければならない(MUST)。
- **FR-002**: 図は、静的生成した HTML に含まれていなければならない(MUST)。スクリプトが動かない環境でも表示され、表示の後に図が現れてレイアウトが動いてはならない(MUST NOT)。
- **FR-003**: 各図は、今の図と同じケースの手順から作り、26 枚のステッカーそれぞれの面が、今の図と一致しなければならない(MUST)。
- **FR-004**: CP と EP の図(27 個)は、ライブラリの既定の配色で描かなければならない(MUST)。今の配色(白い上面など)は引き継がない。
- **FR-005**: CO と EO の図(19 個)は、ライブラリの OLL 用の既定の配色(上面の色だけを残し、ほかは濃い灰色)で描かなければならない(MUST)。今のマスクの色は引き継がない。
- **FR-006**: 図には矢印を描いてはならない(MUST NOT)。図の指定のデータからも、矢印の指定を取り除かなければならない(MUST)。
- **FR-007**: 図の大きさは 100px 四方とし、図を置く欄と、図と手順の文字列の並びは、今と同じでなければならない(MUST)。
- **FR-008**: 図の指定のデータは、ケースの手順と、OLL 型かどうかだけを持つ形にしなければならない(MUST)。マスク、使わない色の名前、幅と高さの値は持たない。
- **FR-009**: 4 ページの見出し、本文、手順の文字列、リンクは、変えてはならない(MUST NOT)。
- **FR-010**: 使わなくなった描画のライブラリ(sr-puzzlegen)は、依存から外さなければならない(MUST)。キューブの図で使っているライブラリ(sr-visualizer)は外してはならない(MUST NOT)。
- **FR-011**: 本文の比較の仕組みは、図が HTML に含まれる形になっても、Megaminx の 4 ページで、図の数を本番サイトと正しく比べられなければならない(MUST)。図の見た目の変更は、この Spec に記録した意図した変更として扱う。
- **FR-012**: 新しいライブラリは、採用前に、開発サーバーと静的生成の出力の両方で動くことを spike で検証しなければならない(MUST、原則 VIII)。
- **FR-013**: サイトは、引き続き静的生成のみで出力しなければならない(MUST)。`legacy/` 配下のファイルを変更してはならない(MUST NOT)。

### Key Entities *(include if feature involves data)*

- **Megaminx の図の指定**: 1 つの図を表す。ケースの手順(そのケースを揃える手順)と、OLL 型かどうか(上面の色だけを示す図か)を持つ。ページごとに、描画先の id(`megacase1` など)をキーにして並べる。
- **Megaminx のケース**: 図と、手順の文字列を持つ(003 から変えない)。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: スクリプトを無効にしたブラウザーで 4 ページを開いたとき、表示されない図が 0 件である(計 46 個)。
- **SC-002**: 46 個の図すべてで、26 枚のステッカーの面が今の図と一致する(不一致 0 件)。
- **SC-003**: 46 個の図すべてで、矢印が 0 本である。CP と EP の図はライブラリの既定の配色、CO と EO の図は OLL 用の既定の配色である。
- **SC-004**: 4 ページで、本文のテキスト、リンク、画像の、本番サイトとの差分が 0 件であり、図の数が本番サイトと一致する。
- **SC-005**: 運営者が、狭い画面と広い画面の両方で 4 ページを見たとき、図と手順の並び、図の大きさに、今と比べて気づくずれがない(配色と矢印の変化を除く)。
- **SC-006**: Megaminx の 4 ページを開くときに読み込むスクリプトの量が、今より減る。
- **SC-007**: Lint、型チェック、静的生成、出力の検証が、すべて成功する。

## Assumptions

- 図の見た目は、ライブラリの見た目(配色、線の太さ、形)にそのまま従う。線の色や背景(透明)も、ライブラリの既定とする。
- 図には、代わりの文字(読み上げ用の説明など)を新しく加えない。本文のテキストを変えないため(FR-009)。
- ライブラリは、同じ指定からどの環境でも同じ図を作る。そのため、静的生成のときとブラウザーで、図が食い違うことはない。
- 事前の調査(2026-11-24)で、46 個すべてについて、今の図とライブラリで同じ手順から作った図の、ステッカーごとの面が一致することを確かめた。手順の解釈(逆にする、括弧、前置きの U)は同じである。
- 今の図の指定は、配色(27 個、すべて同じ)とマスク(19 個、すべて「上面以外の全面」)の 2 種類だけである。そのため、指定は「OLL 型かどうか」の区別で足りる。
- 本番サイトは、003 と 004 を公開した新サイトであり、図は「id を持つ空の欄」として HTML に含まれている。本文の比較では、この欄の数と、この Spec で HTML に含める図の数をそろえて比べる。
- テストコードは、この Spec では必須としない。ただし、Lint と型チェックは必須である(原則 V)。

## 現行の内容から変更した箇所

図の見た目の変更は、運営者の指示による意図した変更である(Constitution 原則 IV:パリティ確認後の別の Spec)。本文の比較の例外として扱う。

| ページ | 場所 | 現行の内容 | 変更後の内容 | 理由 |
|---|---|---|---|---|
| `/megaminx/megaminx-cp` | 15 個の図 | 白い上面の配色、矢印あり、スクリプトで描画 | ライブラリの既定の配色、矢印なし、HTML に含める | 運営者のライブラリに置き換えるため |
| `/megaminx/megaminx-ep` | 12 個の図 | 同上 | 同上 | 同上 |
| `/megaminx/megaminx-co` | 16 個の図 | 上面は白、ほかは黒に近い灰色(マスク)、スクリプトで描画 | 上面は薄い灰色、ほかは濃い灰色(OLL 用の既定の配色)、HTML に含める | 同上 |
| `/megaminx/megaminx-eo` | 3 個の図 | 同上 | 同上 | 同上 |
