# Feature Specification: キューブ系の解法ページの移植

**Feature Branch**: `002-cube-solution-pages`

**Created**: 2026-11-18

**Status**: Draft

**Input**: User description: "キューブ系の解法ページ(pll、oll、f2l、bld、fmc の計13ページ)を、legacy/pages/ から新サイト(Nuxt 4 + TypeScript、静的生成のみ)へ移植する。対象は /pll/pll-view、/pll/pll-chances、/pll/pll、/pll/two-sided-pll、/oll/oll、/oll/coll、/f2l/f2l、/f2l/f2l-advanced、/f2l/winter-variation、/bld/bld-introduction、/bld/bld-method、/bld/old-pochmann-corner、/fmc/intro-fmc。現行サイトと同じ URL、内容、見た目、挙動を再現する(パリティ優先、原則 IV。明らかな誤字は例外として直し記録する)。001-site-foundation で作った共通レイアウトの上に載せる。megaminx、clock、other は別の Spec で扱う。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 手順の一覧ページで、図と手順を見比べられる (Priority: P1)

訪問者は、PLL、OLL、COLL、F2L、発展形 F2L、Winter Variation の手順ページを開き、ケースごとに、キューブの状態を示す図と、その手順(両手、片手、最少手数などの種類つき)を並べて見ることができる。内容、ケースの並び、図の見た目は、現行サイトと同じである。

**Why this priority**: サイトでもっとも参照される、手順の一覧ページ群である。図と手順の対応が崩れると、ページの価値がなくなる。図を描く手段(原則 VIII の spike の対象)もここで決まり、他のページの前提になる。

**Independent Test**: `/pll/pll`、`/pll/pll-view`、`/oll/oll`、`/oll/coll`、`/f2l/f2l`、`/f2l/f2l-advanced`、`/f2l/winter-variation` を開き、各ケースの見出し、図、手順の文字列が、現行サイトと同じ数、同じ順序、同じ内容で表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 訪問者が `/pll/pll` を開いている、**When** ページを下までスクロールする、**Then** 21 の PLL ケースが、現行と同じ見出し、図(矢印つき)、手順の文字列で、同じ順序に並んでいる。
2. **Given** 訪問者が手順の一覧ページを開いている、**When** 各ケースの図を見る、**Then** 図は、現行サイトと同じ視点、色、マスク、矢印で、そのケースの状態を示している。
3. **Given** 訪問者がモバイル幅で手順の一覧ページを開いている、**When** ケースを見る、**Then** 図と手順が現行サイトと同じく横に並び、手順の文字列が読める。
4. **Given** 訪問者が静的に生成されたページを開いた、**When** 図の表示が終わる、**Then** すべてのケースに図が表示され、空欄や崩れた図が0件である。

---

### User Story 2 - 解説ページを、図や表とともに読める (Priority: P2)

訪問者は、PLL の確率、PLL 2側面判断、目隠し(BLD)の入門と解法、Old Pochmann method(corner)、最少手数競技(FMC)の紹介のページを開き、本文、見出し、表、図、画像、外部へのリンクを、現行サイトと同じ内容で読むことができる。

**Why this priority**: 文章が中心のページで、手順の一覧ほど参照されないが、パリティの対象である。一部(PLL の確率、Old Pochmann、2側面判断)は US1 と同じ図の描き方や、画像ファイルを使う。

**Independent Test**: `/pll/pll-chances`、`/pll/two-sided-pll`、`/bld/bld-introduction`、`/bld/bld-method`、`/bld/old-pochmann-corner`、`/fmc/intro-fmc` を開き、見出し、本文、表、図、画像、リンクが、現行サイトと同じ内容と順序で表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 訪問者が `/pll/two-sided-pll` を開いている、**When** 判断パターンの画像を見る、**Then** 現行と同じ画像が、同じ順序と説明文で表示される。
2. **Given** 訪問者が解説ページの外部リンク(参考 PDF、PLL Trainer、参考サイトなど)を選ぶ、**When** リンクを開く、**Then** 現行サイトと同じ外部の URL へ移動する。
3. **Given** 訪問者が `/pll/pll-chances` を開いている、**When** 各パターンの図と確率を見る、**Then** 現行と同じ図、数値、説明が表示される。

---

### User Story 3 - メニューから全ページへ移動でき、404 にならない (Priority: P2)

訪問者は、ヘッダーの F2L、OLL、PLL、BLD、FMC のメニューにある全項目から、対応するページへ移動できる。現行サイトと同じ URL で直接開いても、同じページが表示される。

**Why this priority**: 001 の時点では、これらのメニュー項目は 404 になっている。URL の互換性(原則 II)を、キューブ系の範囲で満たす。

**Independent Test**: 静的生成の出力に、対象の 13 パスがすべて含まれていることを確認し、各メニュー項目を選んでページが表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 訪問者が任意のページを開いている、**When** F2L、OLL、PLL、BLD、FMC のメニューの項目を選ぶ、**Then** 対応するページが、共通のヘッダーとフッターとともに表示される。
2. **Given** 訪問者が対象の 13 パスのいずれかを、ブラウザーで直接開く、**When** ページを読み込む、**Then** 404 にならず、そのページが表示される。
3. **Given** サイトを静的生成した、**When** 出力を確認する、**Then** 対象の 13 パスのページがすべて含まれている。

---

### User Story 4 - 運営者が、直した誤字を確認できる (Priority: P3)

運営者は、移植の際に直した明らかな誤字・誤記の一覧を、Spec の文書で確認できる。一覧には、ページ、現行の表記、修正後の表記が記録されている。

**Why this priority**: 原則 IV の例外の運用に必要な記録である。ページの表示そのものより優先度は低い。

**Independent Test**: 修正の記録を開き、記録された各修正について、新サイトのページが修正後の表記になっていること、記録にない差分が現行サイトとの間にないことを確認する。

**Acceptance Scenarios**:

1. **Given** 移植の際に誤字を直した、**When** 運営者が修正の記録を見る、**Then** ページ、現行の表記、修正後の表記、理由が記録されている。
2. **Given** 誤字かどうか判断に迷う表記がある、**When** 移植する、**Then** 現行の表記のまま残し、修正の候補として記録する。

---

### Edge Cases

- 図の表示にスクリプトが必要な場合: スクリプトが動く前(静的生成された直後の HTML)でも、ページの本文と手順の文字列は読める。図は、スクリプトの実行後に表示される。
- 図の描画に失敗した場合: そのケースの図の領域が空になっても、手順の文字列と他のケースの表示は崩れない。
- 同じページに多数の図がある場合(PLL の 21 ケースなど): すべての図が表示され、現行サイトと比べて、運営者がスクロールやページの操作を体感で遅いと感じない。
- 外部リンクの先が既に存在しない場合(参考 PDF など): リンク先は現行のまま残す。リンク切れの対応は、パリティの範囲外として別の Spec で扱う。
- `http://` で始まる外部リンク: 現行の URL のまま残す。
- 狭い画面で、長い手順の文字列や表がある場合: 現行サイトと同じ折り返しや表示になり、ページ全体が横にはみ出さない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: サイトは、次の 13 パスのページを、現行サイトと同じパスで提供しなければならない(MUST)。`/pll/pll-view`、`/pll/pll-chances`、`/pll/pll`、`/pll/two-sided-pll`、`/oll/oll`、`/oll/coll`、`/f2l/f2l`、`/f2l/f2l-advanced`、`/f2l/winter-variation`、`/bld/bld-introduction`、`/bld/bld-method`、`/bld/old-pochmann-corner`、`/fmc/intro-fmc`。
- **FR-002**: 各ページの見出し、本文、手順の文字列、表、リンクは、現行サイト(`legacy/pages/` の対応するファイル)と同じ内容と順序でなければならない(MUST)。ただし、FR-008 で記録した誤字の修正は除く。
- **FR-003**: キューブの状態を示す図は、現行サイトと同じケースに対して、同じ視点、配色、マスク、矢印で表示しなければならない(MUST)。
- **FR-004**: 現行サイトで画像ファイルとして表示している図(PLL の GIF、2側面判断の PNG)は、同じ画像を、同じ順序と説明文で表示しなければならない(MUST)。
- **FR-005**: 各ページは、001 で作った共通のヘッダーとフッターの中に表示しなければならない(MUST)。
- **FR-006**: 各ページの見た目(レイアウト、余白、図と手順の並び、モバイル幅での表示)は、現行サイトと同等でなければならない(MUST)。デザインの刷新や機能の追加を行ってはならない(MUST NOT)。
- **FR-007**: 外部へのリンクは、現行サイトと同じ URL でなければならない(MUST)。
- **FR-008**: 移植の際に明らかな誤字・誤記を直した場合は、ページ、現行の表記、修正後の表記、理由を、この Spec の文書に記録しなければならない(MUST)。誤字かどうか判断に迷う表記は、直さずに修正の候補として記録する。
- **FR-009**: ページの本文と手順の文字列は、静的生成した HTML に含まれていなければならない(MUST)。図だけは、ブラウザーでの描画に頼ってよい。
- **FR-010**: サイトは、引き続き静的生成のみで出力しなければならない(MUST)。サーバーの実行環境を必要としてはならない(MUST NOT)。
- **FR-011**: 図を描く外部ライブラリを使う場合は、採用前に、開発サーバーと静的生成の出力の両方で動くことを spike で検証しなければならない(MUST、原則 VIII)。
- **FR-012**: megaminx、clock、other、トップページの中身は、この Spec の対象外とする。これらのメニュー項目は、引き続き 404 のままでよい。
- **FR-013**: `legacy/` 配下のファイルを変更してはならない(MUST NOT)。

### Key Entities *(include if feature involves data)*

- **解法ページ**: 13 のページそれぞれ。パス、見出し、本文、手順のケース、画像を持つ。移植元は `legacy/pages/` の対応するファイルである。
- **手順のケース**: 手順の一覧ページの1項目。名前(見出し)、図の指定(視点、配色、マスク、矢印、状態)、手順の文字列の並び(両手、片手、最少手数などの種類つき)を持つ。
- **画像**: 現行サイトが画像ファイルとして表示している図(PLL の GIF 13 枚、2側面判断の PNG)。移植元は `legacy/assets/images/` である。
- **誤字の修正の記録**: 直した、または直す候補とした表記の一覧。ページ、現行の表記、修正後の表記、理由を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 対象の 13 パスのすべてが、静的生成の出力に含まれ、メニューと直接のアクセスの両方で表示される。404 は0件である。
- **SC-002**: 各ページの手順のケース数、手順の文字列、見出しが、現行サイトと比べて、記録した誤字の修正を除き、不足や相違が0件である。
- **SC-003**: 手順の一覧ページで、図が表示されないケースが0件である。
- **SC-004**: 運営者が、狭い画面と広い画面の両方で、各ページを現行サイトと並べて比較したとき、レイアウト、図、表の表示に、気づく相違がない。
- **SC-005**: 外部リンクのすべてが、現行サイトと同じ URL を指している。相違は0件である。
- **SC-006**: 移植で直した誤字のすべてが記録されており、記録にない表記の変更が0件である。
- **SC-007**: Lint、型チェック、静的生成、出力の検証が、すべて成功する。

## Assumptions

- 内容の正は `legacy/pages/` の各ファイルとする。現行の本番サイトとの比較は、運営者が目視で行う。
- 図を描く手段(現行と同じ `sr-visualizer` を使うか、代替にするか)は、この Spec では決めず、Plan で spike の結果をもとに決める(原則 VIII)。
- 現行サイトの画像は、ビルド時にファイル名へハッシュが付いた URL で配信されている。この URL は外部から直接参照される前提のものではないため、画像の URL の一致は求めない。表示される画像の内容が同じであればよい。Constitution 1.1.1 で、ビルドが付けたハッシュ付きの URL は引き継ぎの対象外と明記した。
- 現行のページには、ページごとのタイトルや説明の meta タグがない(サイト全体で共通)。この Spec でも、ページごとの meta タグは追加しない(機能追加にあたるため)。
- `/f2l/f2l-advanced` の見出し「発展系F2L」は、メニューの表記「発展形F2L」に合わせて直す(2026-11-18 に運営者が決定)。記録は「現行の表記から直した箇所」にある。
- 外部リンクの死活確認と、`http://` から `https://` への変更は、この Spec の対象外とする。
- テストコードは、この Spec では必須としない。ただし、Lint と型チェックは必須である(原則 V)。
