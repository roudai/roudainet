# Feature Specification: Megaminx PLL の判断基準のページ

**Feature Branch**: `006-megaminx-pll`

**Created**: 2026-11-25

**Status**: Implemented

**Input**: User description: "メガミンクスの PLL(151 ケース)の判断基準を説明するページ /megaminx/megaminx-pll を新しく作る。運営者が判断基準の文章を 1 ケースずつ自分で書いていくための土台で、この Spec では文章は書かず、枠だけを作る。ケースの元は運営者の MegaminxImageEditor の PLL の項目で、サイトが使っている megaminx-image@1.0.0 の PLL_CASES(megaminx-image/cases)と、名前・手順が 151 ケースすべてで一致する。決定事項:(1) 1 ページに全部並べると長すぎるため、ページの中のタブで行き来する。タブの先頭は「基礎知識」(偽ペア、偽バーなど、PLL 判断の上での基礎知識を説明する。節ごとに見出し・段落・例の図。最初は「偽ペア」「偽バー」の 2 節を空で用意し、文章は運営者が書く)。続けて、覚える順の段階ごとの 27 タブ(F1・A・E・H・U・Z・Q・D・F2–5・J・M・N・T・V・W・Y・B・R・P・S・C・G・I・K2・L・K1・X)。覚える順は、エディターの data/pll/learn_order.json(出典:さむぶろぐ「Megaminx PLL 全手順会議議事録」前編・後編)を写す。段階の見出しには、エディターのグループの説明(A: 3 corner CP など)を添える。(2) 各ケースに、ケース名、画像(megaminx-image の既定の配色、100px。既存の MegaminxImage を使う)と手順を横に並べ、その下に判断基準を書く場所を置く。判断基準は 1 つの TS ファイルに「ケース名 → 段落の文字列の配列」で書き、空のケースは「準備中」と出す。(3) 選んだタブは URL のハッシュで表し、直接開ける。(4) ヘッダーの Megaminx のメニューの最後に「Megaminx PLL」を足す。(5) 本番に無い新しいページなので、出力の検証の対象には含め、本番とのパリティの確認の対象には含めない。新しい依存は無い。Constitution 原則 IV:パリティ確認後の別の Spec としての機能の追加である。"

**位置付け**: Constitution の原則 IV により、機能の追加は、パリティを確認した後の別の Spec で行う。003 と 004 は公開済み(パリティ確認済み)で、この Spec は新しいページを 1 つ足す。既存のページの内容は変えない(ヘッダーのメニューに 1 項目を足すことを除く)。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 覚える順の段階ごとに、PLL のケースを見る (Priority: P1)

訪問者は、Megaminx PLL のページを開き、上に並んだタブから覚える順の段階(F1、A、E など)を選ぶ。選んだ段階のケースが、覚える順に、ケース名、画像、手順の組で並ぶ。段階の見出しには、その段階の名前と、グループの特徴の説明(「A (3 corner CP)」など)が付く。別のタブを選ぶと、その段階に切り替わる。

**Why this priority**: 151 ケースを、長すぎない単位で見て回れることが、このページの土台である。判断基準の文章も、この単位の中に置く。

**Independent Test**: ページを開き、27 個の段階のタブをすべて順に選んで、各段階のケースが覚える順に表示され、151 ケースが、ちょうど 1 回ずつどこかの段階に表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 訪問者がページを開いている、**When** 段階のタブ(たとえば「A」)を選ぶ、**Then** A の 4 ケース(A1+、A1-、A2+、A2-)が、ケース名、画像、手順の組で、この順に表示され、ほかの段階のケースは表示されない。
2. **Given** 段階のタブを選んでいる、**When** 見出しを見る、**Then** 段階の名前とグループの説明(「A (3 corner CP)」)が表示されている。グループの一部だけの段階(F1、F2–5、K2、K1)も、そのグループの説明が付く。
3. **Given** ページを開いている、**When** 27 個の段階のタブを順にすべて選ぶ、**Then** 計 151 ケースが表示され、同じケースが 2 回出ることも、出ないケースもない。

---

### User Story 2 - 各ケースの判断基準と、基礎知識を読む (Priority: P1)

訪問者は、各ケースの画像と手順の下で、そのケースの判断基準の説明を読む。また、ページを開いて最初に出る「基礎知識」のタブで、偽ペア、偽バーなど、PLL を判断する上での基礎知識の説明と、その例の図を読む。運営者は、判断基準と基礎知識の文章を、1 つずつ自分で書き足していく。まだ書いていないところには「準備中」と表示される。

**Why this priority**: 判断基準の説明がこのページの目的である。この Spec では文章は書かず、運営者が書き足すだけで表示される枠を作る。

**Independent Test**: ページを開くと「基礎知識」のタブが出て、「偽ペア」「偽バー」の節が「準備中」と表示されることを確かめる。運営者が、1 ケースの判断基準と、基礎知識の 1 節に、試しに文章(と例の図)を書き足し、静的生成し直すと、その位置に表示されることを確かめる。

**Acceptance Scenarios**:

1. **Given** 訪問者がページを開いた(タブを指定していない)、**When** 最初の表示を見る、**Then** 「基礎知識」のタブが選ばれており、「偽ペア」「偽バー」の 2 つの節が、見出し付きで表示されている。
2. **Given** 判断基準を書いていないケース、**When** 訪問者がそのケースを見る、**Then** 画像と手順の下に「準備中」と表示される。
3. **Given** 運営者が、あるケースの判断基準を 2 段落書き足した、**When** 静的生成し直したページでそのケースを見る、**Then** 画像と手順の下に、その 2 段落がその順で表示される。
4. **Given** 運営者が、基礎知識の節に段落と例の図(PLL のケース名、または手順で指定)を書き足した、**When** 静的生成し直したページで基礎知識のタブを見る、**Then** その節の見出しの下に、段落と例の図(と、添えた説明の文字)が表示される。
5. **Given** 運営者が、基礎知識に新しい節を書き足した、**When** 静的生成し直したページを見る、**Then** その節が、書いた順で表示される。

### User Story 3 - 段階を直接開き、メニューからたどる (Priority: P2)

訪問者は、ヘッダーの Megaminx のメニューから「Megaminx PLL」を選んでページを開く。特定の段階を指したリンク(たとえば K2 の段階)を開くと、その段階が選ばれた状態で表示される。タブを選ぶと、アドレスもその段階を指すものに変わるため、そのアドレスを人に伝えられる。

**Why this priority**: ページへの入口と、特定の段階を共有できることは便利だが、ページの中の表示(US1、US2)が先にあって意味を持つ。

**Independent Test**: ヘッダーのメニューからページを開けること、段階を指したアドレスを直接開くとその段階が表示されること、タブを選ぶとアドレスが変わり、ページの先頭へ飛ばないことを確かめる。

**Acceptance Scenarios**:

1. **Given** 訪問者がサイトのどのページにいても、**When** ヘッダーの Megaminx のメニューを開く、**Then** 最後(Megaminx CP の下)に「Megaminx PLL」があり、選ぶとこのページが開く。
2. **Given** K2 の段階を指したアドレス、**When** 訪問者がそれを直接開く、**Then** K2 のタブが選ばれ、K2 のケースが表示される。
3. **Given** 訪問者がページを開いている、**When** タブを選ぶ、**Then** アドレスがその段階を指すものに変わり、表示の位置はページの先頭へ飛ばない。再読み込みしても、同じ段階が表示される。
4. **Given** 存在しない段階を指したアドレス、**When** 訪問者がそれを開く、**Then** 「基礎知識」のタブが表示される。

---

### Edge Cases

- 狭い画面(幅 375px 程度)の場合: 28 個のタブは折り返して並び、ページが横にはみ出さない。画像と手順は重ならない(005 と同じく、画像は欄の幅まで縮む)。
- スクリプトが動かない環境: 見出しと「基礎知識」のタブの中身は表示される。ほかの段階への切り替えはできなくてよい。
- 手順の文字列が長いケース: 手順は折り返し、画像と重ならない。
- 判断基準のデータに、存在しないケース名を書いた場合: 静的生成の前の確認(型チェックなど)で気づける。表示には出ない。
- 基礎知識の例の図に、存在しないケース名や読めない手順を書いた場合: 静的生成のときに気づける(誤った図のまま公開しない)。
- 同じページに図が多い(計 151 個 + 基礎知識の例): 表示とタブの切り替えが、体感で遅くない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: サイトは、新しいページ `/megaminx/megaminx-pll` を提供しなければならない(MUST)。見出しは「Megaminx PLL」とする。
- **FR-002**: ページは、タブで中身を切り替えなければならない(MUST)。タブは、先頭に「基礎知識」、続けて覚える順の 27 段階(F1、A、E、H、U、Z、Q、D、F2–5、J、M、N、T、V、W、Y、B、R、P、S、C、G、I、K2、L、K1、X)の順に並べる。一度に表示するのは、選んだ 1 つのタブの中身だけとする。
- **FR-003**: 覚える順の段階とその中のケースの並びは、運営者の MegaminxImageEditor の覚える順(出典:さむぶろぐ「Megaminx PLL 全手順会議議事録」前編・後編)と同じでなければならない(MUST)。151 ケースが、ちょうど 1 回ずつ、いずれかの段階に含まれる。出典をサイトのデータに記録する。
- **FR-004**: 各段階の見出しには、段階の名前と、そのケースのグループの特徴の説明(MegaminxImageEditor と同じ表記。たとえば「A (3 corner CP)」)を表示しなければならない(MUST)。
- **FR-005**: 各ケースは、ケース名、画像、手順を表示しなければならない(MUST)。画像と手順は、既存の Megaminx のページ(CP、EP)と同じく横に並べ、画像は同じ見た目(ライブラリの既定の配色、100px、狭い欄では欄の幅まで縮む)とする。名前と手順は、運営者のライブラリの PLL のケースの値と同じとする。
- **FR-006**: 各ケースの画像と手順の下に、判断基準の説明を表示しなければならない(MUST)。説明は、運営者が 1 つのファイルに、ケースごとに段落の並びとして書き足していく。書いていないケースは「準備中」と表示する。
- **FR-007**: 判断基準を書くファイルには、151 ケースすべての欄を、覚える順に、空の状態で用意しなければならない(MUST)。段階ごとに区切りを付け、どこに書けばよいか分かるようにする。
- **FR-008**: 「基礎知識」のタブは、節を並べて表示しなければならない(MUST)。各節は、見出し、段落の並び、例の図(任意。PLL のケース名か手順で指定し、説明の文字を添えられる)を持つ。運営者は節を好きなだけ書き足せる。最初は「偽ペア」「偽バー」の 2 節を、中身が空の状態で用意する。段落が空の節は「準備中」と表示する。(実装の後の運営者の指示で、FR-016 のとおりに改めた)
- **FR-009**: 選んだタブは、ページのアドレス(URL のハッシュ)で表さなければならない(MUST)。段階を指したアドレスを直接開くと、その段階を表示する。タブを選ぶと、アドレスが変わり、表示の位置はページの先頭へ飛ばない。アドレスで指していない、または存在しない段階を指している場合は「基礎知識」を表示する。
- **FR-010**: ヘッダーの Megaminx のメニューの最後(「Megaminx CP」の下)に、このページへの項目「Megaminx PLL」を足さなければならない(MUST)。ほかのメニューの項目は変えない。
- **FR-011**: ページの見出し、タブ、すべてのタブの中身(151 ケースの名前、手順、画像、判断基準)は、静的生成した HTML に含まれていなければならない(MUST)。
- **FR-012**: 出力の検証は、このページが出力に含まれることを確かめなければならない(MUST)。本番とのパリティの確認は、このページを対象にしない(本番に無いため)。
- **FR-013**: 判断基準と基礎知識の文章は、この Spec では書かない(MUST NOT)。枠と「準備中」の表示だけを作る。
- **FR-015**: 各段階のタブは、見出しの下に、そのグループについての一言を表示しなければならない(MUST)。一言は運営者が判断基準と同じファイルに書き、27 段階すべての欄を空の状態で用意する。空のときは「準備中」と表示する。(実装の後に運営者の指示で追加)
- **FR-016**: 「基礎知識」の節は、本物と偽物を左右に並べて比べる形にできなければならない(MUST)。比べる左右の欄は、それぞれ見出し・段落・例の図を持ち、左に本物、右に偽物を置く。狭い画面では左右の欄を縦に積む。比べる形の節では、節の段落は欄の上の導入とし(空なら何も出さない)、段落が空の欄に「準備中」と表示する。最初は「ペアと偽ペア」「バーと偽バー」「ブロックと偽ブロック」の比べる形の 3 節と、比べない形の「ヘッドライト」の 1 節を、中身が空の状態で用意する。(実装の後に運営者の指示で追加)
- **FR-017**: 基礎知識の例の図は、例の部分(ペアならエッジとコーナーなど)のステッカーだけに色を残し、それ以外の側面を濃い灰色にして示せなければならない(MUST)。図の向きも変えられる。最初は、ペア・偽ペア・バー・偽バー・ブロック・偽ブロック・ヘッドライトの 7 つに、例を下の面に置いた図を 1 つずつ用意する。偽物の定義は運営者の示した資料による(偽ペア:コーナーの配色が逆だったらペアになっていた状態。偽バー:両側のコーナーの配色が逆だったらバーになっていた状態。偽ブロック:コーナーの配色が逆だったらブロックになっていた状態)。既存の Megaminx のページの図は変えない(MUST NOT)。(実装の後に運営者の指示で追加)
- **FR-014**: サイトは、引き続き静的生成のみで出力しなければならない(MUST)。新しい依存を加えない。`legacy/` を変更しない(MUST NOT)。

### Key Entities *(include if feature involves data)*

- **PLL のケース**: 名前(A1+ など)、グループ(A など)、手順を持つ。151 件。値は運営者のライブラリの PLL のケースから読む。
- **覚える順の段階**: 名前(F1、A、F2–5 など)と、覚える順に並べたケースの名前の並びを持つ。27 件。
- **グループの説明**: グループの名前と、その特徴の短い説明(「3 corner CP」など)。25 件。
- **判断基準**: ケースの名前ごとの、段落の並び。運営者が書き足す。
- **基礎知識の節**: 見出し、段落の並び、例の図の並び(各図は、ケースの名前か手順と、任意の説明の文字)。運営者が書き足す。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 27 個の段階のタブを順に選ぶと、計 151 ケースが表示され、重複と漏れが 0 件である。
- **SC-002**: ページを開いたときの最初の表示で、「基礎知識」のタブと、その節(FR-016 の 4 節)が表示される。
- **SC-003**: 運営者が、1 ケースの判断基準または基礎知識の 1 節に文章を書き足すと、ほかのファイルを変えずに、静的生成し直したページのその位置に表示される。
- **SC-004**: 段階を指したアドレスを直接開くと、28 個のタブのどれについても、そのタブが表示される。
- **SC-005**: 狭い画面と広い画面の両方で、タブ、画像、手順が重ならず、ページが横にはみ出さない。
- **SC-006**: ヘッダーの Megaminx のメニューから、このページに 1 回の操作でたどり着ける。
- **SC-007**: 既存のページの本番とのパリティの確認の結果が、この Spec の前(005 の公開後)から変わらない。
- **SC-008**: Lint、型チェック、静的生成、出力の検証が、すべて成功する。

## Assumptions

- PLL のケースの名前、グループ、手順は、運営者のライブラリ(megaminx-image 1.0.0)の値を使う。事前の調査(2026-11-25)で、MegaminxImageEditor の PLL のデータと 151 ケースすべてで一致することを確かめた。
- 覚える順の段階とグループの説明は、ライブラリに無いため、MegaminxImageEditor のデータから値を写す。段階の名前は、MegaminxImageEditor が表示している名前と同じにする。
- 画像は、005 で作った Megaminx の図の仕組みを使う(既定の配色。矢印は無い)。
- 手順の表示は、ライブラリの PLL のケースの手順(AUF を含まない)とする。
- ページごとのタイトルや meta タグは、ほかのページと同じく付けない。
- 「準備中」の表示は、すべて同じ文言とし、本文より薄い色にする。
- テストコードは、この Spec では必須としない。ただし、Lint と型チェックは必須である(原則 V)。

## 現行の内容から変更した箇所

既存のページへの変更は、運営者の指示による機能の追加に伴うもの(Constitution 原則 IV:パリティ確認後の別の Spec)である。

| ページ | 場所 | 現行の内容 | 変更後の内容 | 理由 |
|---|---|---|---|---|
| すべてのページ | ヘッダーの Megaminx のメニュー | Megaminx EO、CO、EP、CP の 4 項目 | 最後に「Megaminx PLL」(`/megaminx/megaminx-pll`)を足した 5 項目 | 新しいページへの入口 |
